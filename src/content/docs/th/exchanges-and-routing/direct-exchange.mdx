## routing แบบ match เป๊ะ

**direct exchange** route message ไปยัง queue ที่มี **binding key** ตรงกับ **routing key** ของ message เป๊ะ ๆ ไม่มี pattern ไม่มี wildcard — เทียบ string ให้เท่ากันตรง ๆ มันคือ exchange type ที่ง่ายที่สุด และเป็นตัวที่หยิบมาใช้เมื่อ message มีปลายทางเป็นหมวดหมู่ที่ชัดเจนหมวดเดียว

จริง ๆ คุณเคยใช้ direct exchange มาแล้วโดยไม่รู้ตัว: **default exchange** คือ direct exchange ที่ไม่มีชื่อ ซึ่งทุก queue จะถูก bind เข้าไปด้วยชื่อของตัวเองโดยอัตโนมัติ นั่นคือเหตุผลที่ publish ไปที่ routing key `hello` ด้วย exchange เป็น string ว่าง แล้วมันไปลงที่ queue ชื่อ `hello`

## ตัวอย่าง: log ตาม severity

สมมติคุณส่ง log message และอยากให้ log ระดับ `error` ไปเข้า queue หนึ่ง (ไว้ alert) และ `info` ไปอีก queue หนึ่ง (ไว้ archive) ก็ประกาศ direct exchange, bind แต่ละ queue ด้วย severity เป็น binding key แล้ว publish โดยใช้ severity เป็น routing key

## หลาย binding, key เดียวกัน

direct exchange ไม่ได้จำกัดที่ queue เดียวต่อ key ถ้ามี queue **สองตัว** bind ด้วย key `error` เหมือนกัน message `error` ตัวเดียวจะถูก copy ไป **ทั้งสอง** queue — คุณจึงผสม routing แบบ match เป๊ะเข้ากับการ fan-out นิด ๆ ได้ ในทางกลับกัน queue เดียวก็ bind ได้หลาย key (bind `errors` กับทั้ง `error` และ `critical`) เพื่อรวบหลายหมวดมาไว้ด้วยกัน

<Callout title="สรุปหนึ่งบรรทัด">
direct exchange route ด้วยการเทียบ **routing key ให้เท่ากันเป๊ะ**: message ไปเข้าทุก queue ที่ binding key ตรงกับ routing key แบบ string ต่อ string เหมาะเมื่อ message แบ่งเป็นหมวดหมู่ที่ชัดเจนมีชื่อ (log severity, event type) ส่วน default exchange ที่ไม่มีชื่อ ก็คือ direct exchange ที่ทุก queue ถูก bind ด้วยชื่อตัวเอง
</Callout>
